# Генерация юмористических текстов на македонском языке

Курсовая работа для магистратуры. Цель проекта — построить нейросеть, способную генерировать юмористические тексты на македонском языке, опираясь на корпус художественной литературы.

> Результаты и выводы будут добавлены по мере завершения всех этапов работы.

## Конвейер обработки текста

Проект построен как конвейер из 7 этапов, каждый из которых подготавливает данные для следующего:

| Этап | Что происходит | Инструмент в проекте |
|------|---------------|---------------------|
| 1. Извлечение | Получение текста из файлов корпуса. Тексты уже в формате `.txt` (UTF-8), OCR не нужен | Скрипты на Python (`chardet` для проверки кодировки) |
| 2. Токенизация | Разбиение текста на слова и предложения | CLASSLA (форк Stanza для южнославянских языков) |
| 3. Лемматизация | Приведение слов к начальной форме (книгите → книга, трчаше → трча). Плюс POS-тегирование и dependency parsing | CLASSLA (лемматизация, POS) + spaCy `mk_core_news_lg` (dependency parsing) |
| 4. Векторизация | Превращение слов в числовые вектора (эмбеддинги), чтобы компьютер мог считать расстояние между словами | FastText (`cc.mk.300.bin`, 300-мерные вектора от Facebook) |
| 5. Индексация | Построение семантического графа (вершины = концепты, ребра = отношения) и индексация весов слов в документах | NetworkX (граф) + BM25 (веса слов по документам) |
| 6. Поиск | Нахождение неожиданных связей между концептами в графе — это основа юмора (семантически далекие слова, неожиданно связанные) | Cosine similarity по FastText-эмбеддингам + анализ графа |
| 7. Генерация | Создание нового юмористического текста на базе найденных паттернов | Собственная нейросеть на PyTorch (LSTM), обученная на корпусе |
| 8. Трансляция | Перевод сгенерированной шутки с македонского на русский, чтобы можно было оценить, насколько она смешная | Helsinki-NLP/opus-mt-mk-ru (открытая модель перевода) |

Ключевой принцип: каждый следующий этап работает с результатом предыдущего. BM25 и FastText не заменяют лемматизатор — они работают с уже обработанными словами (леммами), которые подготовил CLASSLA. На выходе система показывает шутку на македонском и её перевод на русский.


## Ход работы

### Этап 1. Ревизия и подготовка данных

#### 1A. Инвентаризация и метаданные

Взяла корпус из 128 текстовых файлов в папке `texts/` и Excel-каталог `Naslovi_knigi_tabela .xls` с метаданными (134 записи).

**Сканирование файлов.** Написала скрипт, который обходит все файлы в `texts/`, парсит имена файлов (извлекает номер, автора, название), определяет размер и кодировку каждого файла с помощью `chardet`. Все 128 файлов оказались в кодировке UTF-8 с BOM. Общий объём корпуса — 57.1 МБ. Результат сохранила в `datasets/processed/inventory_raw.csv`.

**Анализ Excel-каталога.** Прочитала каталог через `pandas.read_excel()`, нормализовала названия столбцов в латиницу (`number`, `title_mk`, `author`, `source`, `year`, `genre`, `original_year`). Посчитала заполненность: жанр, автор и название заполнены на 100%, оригинальный год издания — только у 33 из 134 записей (диапазон 1958–2007). Годы-диапазоны вроде "1972 / 1981" привела к первому году. Сохранила в `datasets/processed/catalog_from_excel.csv`.

**Объединение.** Сделала merge двух таблиц по номеру файла. 128 файлов нашли соответствие в каталоге, 10 записей каталога остались без файла на диске (номера 1–5, 7, 8, 78, 84, 92 — в основном литературная критика). Распределение по жанрам: поэзия 57, проза 55, драма 8, критика 7. Результат — `datasets/processed/inventory_merged.csv` (138 строк, 15 столбцов).

#### 1B. Классификация и фильтрация

**Определение языка.** Для каждого из 128 файлов определила язык по характерным символам кириллицы (ѓ, ќ, љ, њ, џ — македонский) и латиницы с диакритиками (ë, ç — албанский). Обнаружила: 98 текстов на македонском, 19 на албанском, 6 на турецком (файлы 126–131 — неожиданная находка, в каталоге они не были помечены как турецкие), 5 — литературная критика и эссеистика.

**Классификация по жанру.** Использовала жанр из каталога (`genre`) как основу и добавила эвристическую проверку по тексту. Исправила ошибку каталога: файлы 06а–06г числились как «Критика» (потому что запись №6 — антология «Македонска битова драма»), а на самом деле это четыре отдельные пьесы — исправила на «Драма». Финальный жанровый состав после фильтрации: 45 поэзия, 40 проза, 9 драма, 4 детская литература.

**Фильтрация.** Оставила 98 текстов — оригинальные македонские художественные произведения. Исключила: 19 албанских, 6 турецких, 5 критика/эссеистика. Результат — `datasets/processed/inventory_classified.csv` (128 строк, 27 столбцов) и `datasets/processed/corpus_filtered.csv` (98 текстов).

#### 1C. Чтение и очистка текстов

Прочитала все 98 отфильтрованных файлов (кодировка UTF-8 с BOM) и провела очистку: удалила BOM-маркеры, нормализовала переносы строк (CRLF → LF), схлопнула множественные пустые строки до одной, убрала управляющие символы и пробелы в конце строк.

**Статистика корпуса:** 4 632 628 слов, 21 922 832 символа (без пробелов). По жанрам: проза — 2.7M слов (40 текстов), поэзия — 935K (45), детская литература — 536K (4), драма — 455K (9).

Из текстов извлекла метаданные (автор найден в 85 из 98 файлов, название — в 74) и сверила с каталогом. Очищенные тексты сохранила в двух форматах: отдельные файлы в `datasets/cleaned_texts/` (98 штук) и сводный `datasets/raw/corpus_texts.csv` (98 строк, 8 столбцов).

#### 1D. Оценка достаточности корпуса и формирование финальных датасетов

**Оценка корпуса.** Корпус содержит 4 632 628 слов — это в 9.3 раза больше порога достаточности (500K слов). Оценила дополнительные источники: Leipzig Corpora (новостные тексты, не подходят для художественной генерации), OSCAR (web crawl, не литература), Wikisource (слишком мало), Project Gutenberg (нет македонских текстов), MANU (не в открытом доступе). Вывод: дополнительные данные не нужны.

**Финальные датасеты.** Расширила `corpus_texts.csv` до полного датасета `corpus_full.csv`, добавив столбцы `id`, `source` и `is_original_mk` (через merge с `corpus_filtered.csv`). Разбила тексты на абзацы — получилось 48 061 абзац (разделение по `\n\n`). Средний размер абзаца зависит от жанра: проза — 958 слов, детская — 239, драма — 37 (реплики), поэзия — 30 (строфы). Провела проверки целостности: все 98 файлов на месте, пустых текстов и дубликатов нет.

#### 1E. Разбиение корпуса и разведочный анализ

**Стратегия разбиения.** Разбила 98 текстов на train/validation/test в пропорции 70/15/15 со стратификацией по жанру. Жанры «Детска книжевност» (всего 4 текста) и «Проза» объединила в одну страту, потому что 4 текста — слишком мало для стратификации. Дополнительно учла группировку по авторам: тексты одного автора попадают строго в одну выборку, чтобы модель не видела стиль автора одновременно в train и test. Мультитекстных авторов оказалось три: Лужина Јелена (4 текста), Јоциќ Светлана (3 текста), Силјан Раде (2 текста).

**Итоговые цифры:**
- train — 69 текстов (3.32M слов)
- validation — 14 текстов (596K слов)
- test — 15 текстов (717K слов)

Информацию о том, какой текст попал в какую выборку, сохранила в `datasets/split_info.csv`. Для каждой выборки подготовила отдельные CSV-файлы с текстами (`datasets/raw/train.csv`, `datasets/validation.csv`, `datasets/test.csv`) и с абзацами (`datasets/raw/train_paragraphs.csv`, `datasets/validation_paragraphs.csv`, `datasets/test_paragraphs.csv`). Сводную статистику корпуса записала в `datasets/corpus_statistics.csv`.

**Разведочный анализ (EDA).** Построила 6 графиков:
- распределение текстов по жанрам (pie chart)
- распределение по объёму текстов (histogram)
- топ-20 авторов по объёму (bar chart)
- тексты по годам издания (scatter plot)
- облако слов (wordcloud)
- разброс объёмов по жанрам (boxplot)

**Основные находки.** Распределение объёмов скошено вправо: медиана — 31 829 слов, но есть несколько очень больших текстов, которые тянут среднее вверх. Только 33 из 98 текстов имеют известный год издания (диапазон 1958–2007). Самые продуктивные авторы по объёму — крупные прозаики.

### Этап 2. NLP-инструменты: лемматизация и токенизация

#### Два подхода к лемматизации

Реализовала два подхода к лемматизации македонского текста, чтобы сравнить их качество:

- **Нейросетевой (CLASSLA)** — форк Stanza для южнославянских языков, поддерживает македонский: токенизация, POS-тегирование, лемматизация.
- **Rule-based (собственный)** — лемматизатор на правилах, основанный на суффиксном анализе и словаре исключений.

#### Обработка корпуса через CLASSLA

Установила CLASSLA 2.2.1 с флагом `--no-deps`, чтобы избежать конфликтов зависимостей. Написала улучшенную функцию обработки, которая разбивает текст по границам предложений (а не по количеству символов), обрабатывает ошибки и ведёт лог статистики. Прогнала все 98 текстов корпуса (~50 минут на CPU). Результаты сохранила в SQLite-базу `datasets/nlp_data.db`.

#### Rule-based лемматизатор

Написала собственный лемматизатор, опираясь на морфологию македонского языка: постпозитивные артикли (-от, -та, -то), классы глагольного спряжения, согласование прилагательных. Использовала гибридный подход: словарь исключений (неправильные формы, местоимения) + суффиксные правила по POS-тегу. Для честного сравнения с CLASSLA использовала те же токены, которые выдала CLASSLA.

#### Gold standard и сравнение

Скачала UD Macedonian-MTB (155 предложений, 1360 токенов с вручную проверенными леммами) для оценки качества.

**Результаты сравнения:**

- CLASSLA accuracy: 85.9% (без учёта регистра) на gold standard
- Rule-based accuracy: 73.6% на gold standard
- CLASSLA лучше на существительных (98.3% vs 68.7%), глаголах (82.3% vs 59.1%), прилагательных (90.9% vs 50.0%)
- Rule-based в 1911 раз быстрее (215 963 vs 113 токенов/сек)
- Основные источники ошибок rule-based: OOV-слова, не покрытые правилами (165), глаголы (115), ошибки при снятии артикля (35)

#### Dependency parsing

CLASSLA не поддерживает dependency parsing для македонского. Установила spaCy с моделью `mk_core_news_lg` — единственный доступный инструмент с готовым dependency parsing для mk. В итоге выбрала гибридный набор: CLASSLA для токенизации/POS/лемматизации, spaCy для dependency parsing.

#### Визуализации

Построила 3 графика по результатам сравнения лемматизаторов: accuracy по POS-тегам, распределение ошибок rule-based, сравнение скорости. Графики сохранила в `temp/visualization/`.
